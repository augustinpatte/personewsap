# Learning Paths Content QA

## Atomicity

Une etape enseigne une seule idee principale. Elle ne doit pas couvrir un chapitre entier, empiler plusieurs notions, ou promettre une maitrise complete.

## Progression

Les stages suivent une progression stable :

- Stage 1 : vocabulaire, intuition, distinctions initiales.
- Stage 2 : mecanismes principaux, relations entre concepts, erreurs frequentes.
- Stage 3 : application, comparaison, petits problemes.
- Stage 4 : autonomie, decisions techniques, analyse critique.
- Stage 5 : limites, arbitrages, conception, evaluation.

## Bilingue

Chaque champ visible existe en francais et en anglais. Les deux versions doivent enseigner le meme concept, au meme niveau, avec un style naturel dans chaque langue.

Les termes techniques anglais peuvent rester en francais lorsqu'ils sont vraiment utilises dans le domaine, mais ils doivent etre utiles et comprehensibles.

## Non-Repetition

Deux etapes proches doivent avoir une difference pedagogique claire : niveau, angle, decision, erreur typique, ou contexte d'application.

Les contextes alternatifs doivent aider le backend a varier les exemples lors d'une reprise ou d'un faible interet utilisateur.

## Safety

La cybersecurite reste defensive. Les etapes peuvent expliquer les risques, les controles, la detection et la reponse, mais ne doivent pas fournir de procedure directement exploitable contre une cible reelle.

La medecine reste educative. Les etapes expliquent les mecanismes, la preuve, le risque et le raisonnement general. Elles ne donnent jamais de diagnostic ou de traitement personnalise.

## Exactness

Le contenu doit rester compatible avec une session de cinq minutes : analogie courte, explication directe, deux ou trois questions maximum, rappel final.

Les domaines sensibles comme finance, sante, droit implicite et securite doivent privilegier les limites, l'incertitude et les conditions d'utilisation.
